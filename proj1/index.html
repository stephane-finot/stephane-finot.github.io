Project Overview

The images we work with in this project are comprised of gray-scale images representing the data captured by the camera for a specific color channel. The challenge arises when each of these color channel images were taken at slightly different times, which causes slight differences in the position of the camera at the time of the image being taken. If you were to try stacking the images right away, it would be misaligned and the final image would contain chromatic aberations. Thus, we need some pre-processing to align the images so that the different channels will line up properly to create a final image that does not have chromatic aberations.

Part 1: Single-scale Alignment

A basic way to align the images is to use a single-scale approach in which we shift the entire color channels across a range of offsets (+ or - 15 pixels)and compute a difference metric to determine which of the tested offsets have the best alignment. This metric can be computed in a few different ways, including using the L2 norm and Normalized Cross-Correlation. L2 norm, or Euclidean Difference, measures the difference between each pixel value in the two images and sums the squared differences, and finally takes the square root of the sum. The best alignment the L2 norm is the one that minimizes this calculated value. Normalized Cross-Correlation normalizes both images to have zero mean by subtracting the overall image mean from each pixel value, and divides by each of the L2 norms, and multiplies these products with each other to calculate correlation. This method ensures that different lighting conditions do not affect the comparison method. The calculated metric is the normalized cross-correlation between the two images, so higher calcualted values mean better alignment with NCC. In this project, I used NCC due to its reliability across different lighting conditions. For these images, the offsets calculated using NCC and L2 norm were identical, so I only present the results of NCC in this section.

To avoid calculations being skewed by the edges of the image, which may contain more artifacts, I cropped the sides of the images before computing the difference metric. Since we are just computing offsets, this cropping will not affect the final image as we will simply shift the full-size image by the returned offsets. Part 2: Multi-Scale Alignment

Single-scale alignment works well for small images, as the range over which we test offsets accounts for a decent percentage of the image (30 pixel-range for a 300 pixel-wide image is 10% of the image width). However, for larger images, this range is a much smaller percentage of the image width, and most likely will not search enough offsets to find the best one as the misalignment is too large. Hence, we must find a way to narrow our search window so that we do not need to iterate over a huge window. We can do this through downsampling the image to make it a smaller size. Then, we can run our single-scale alignment on the downsampled image to find a good offset for the downsampled image. Then, use the offset of this downsampled image to find a smaller range of offsets to test on the full-size image. To make this more effective, I had this process run recursively where I continued downsampled until I reached a base case where the images were in a viable size for single-scale alignment. Through each iteration, you can test a range based off the recursive call below it as it will return an estimate offset. This will continuously pass up a range of offsets to keep testing optimal offsets until we eventually reach the full-resulution to test the image on.

Chasing the Emir of Bukhara

Initially, I had been using the starter-code that aligned the green channel to the blue channel, and then the red channel to the blue channel. This worked almost perfectly for all of the images, with the sole exception of the Emir of Bukhara. The initial tests on the Emir of Bukhara is shown in (1). I tried many different parameters, changing the base case size, base case window, the downsampling factor, and the intermediate windows, to search across more offsets. One of my tests was close, but it was still the same as the "not ok" example so was unsatisfactory. In the project specifications, it was mentioned that our default metrics like NCC might not work when the pixel values were different between channels. Hence, I suspected there was a fundamental issue with how I was searching rather than the size of the search. Throughout my tests, I realized that the green and blue channels always seemed to be aligned so I rendered the image without red to confirm my observation, which is show in (2). When reviewing the template code given, I saw red was being aligned to the blue channel, which evidently was not working. This led me to the idea that perhaps there was more variance between the red and blue channels than between the green and blue channels. Remembering some of the slides from lecture, this might make sense as the red and blue wavelengths are on opposite ends of the visible light spectrum, meaning there would likely be less overlap in the light captured for each of the channels (3). Returning to the idea that our difference metric is searching based on the assumption that pixel values across different channels are similar, it would be logical to try to make the pixel values as similar as possible across channels to make our alignment metric more accurate. Aligning red with an aligned green, instead of blue, would hopefully achieve this goal more effectively than comparing red with blue, as green and red are much closer to each other on the visible spectrum in terms of wavelength. Making this tiny change completely fixed my algorithm, and enabled the same parameters that worked on all the other images to work on the Emir of Bukhara! For consistency, I re-ran all my other images through this new alignment order and used these new offsets. Sometimes they would different by a single pixel from the old offsets, and this likely has to do with the limits of a translation-only alignment. Between the old alignment order and new one, some parts become less aligned while others become more, and this implies we need scale or rotation to find the best alignment. Note: I aligned the red to the aligned green rather than using green as the anchor for both to be able to keep the green and red offsets for the sake of the assignment (instead of having blue and red offsets).
