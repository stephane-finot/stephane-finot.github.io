A.2 Recover Homographies

A homography is a transformation matrix used to map a point in one image plane to another. Formally, we can view this as a map for point p in im1 to p' in im2 and p' = Hp. The homography matrix H is 3×3. Due to the method of calculation, scales do not affect the final output so we lose one degree of freedom. Even though there are 9 variables, we only need 8 variables to define a homography matrix.

[w * x']   [a b c] [x]
[w * y'] = [d e f] [y]
[ w  ]   [g h 1] [1]

After you divide by w and multiply out the denominator, we get two linear equations from each point (one for x' and one for y'):

[x  y  1  0  0  0  -x x'  -y x'] [a b c d e f g h]ᵀ = x'
[0  0  0  x  y  1  -x y'  -y y'] [a b c d e f g h]ᵀ = y'

We get our data points by selecting corresponding points in the two images. For example, the same corner of a building would represent p and p'. Even though we only have 8 degrees of freedom, and therefore in theory only need 8 data points (or 4 corresponding points, each with an x and y) there is some human error when selecting our corresponding points. Hence, it's more effective in practice to select many points, and least squares finds the H that minimizes the sum of squared errors over all points.

A.3 Warp the Images

Now we'll warp the images to be able to match our images. To start with a simpler case, we'll just warp a painting seen from an angle to get the projective view from straight on. This we can cleanly use just 4 points for the 4 corners, and the corresponding points will be a manually defined rectangle. Firstly we multiply our four corners by our homography matrix to get the shape of the output image. Then, for each pixel in this output bounding box, we'll apply H⁻¹ and divide by w to see where it originates from the original image.

If the inverse of a pixel in the bounding box is outside our original image, we can just set it to black. However, it gets more complicated when we think about interpolations when our calculated positions do not land exactly on a pixel. Nearest neighbor simply takes the nearest pixel and sets the output pixel to that value. However, this can cause aliasing. A more effective method is bilinear sampling where we linearly interpolate between the four nearest pixels to calculate a more accurate value for the output pixel.

Nearest Neighbor vs. Bilinear

Nearest neighbor does one sample to the nearest pixel. Bilinear does 4 samples to the 4 closest pixels plus the calculation using the weights, so it takes a bit longer to run. The nearest neighbor process looks more jagged because it just takes the nearest pixel rather than accounting for the surrounding pixels. Bilinear on the other hand takes into account the 4 surrounding pixels, so it results in a much smoother output as edges have smoother gradients if a sampled pixel lands between two pixels in the original. There is the most difference between nearest neighbor and bilinear in the areas that are most stretched, as there is the most aliasing there.

A.4 Blend the Images into a Mosaic

To blend the two images I can warp the left photo into its projection with the homography calculation from the photo warping portion, and just lay that on the right photo that stays in its original position. Procedure:

  1. Alpha: Calculate the alpha of the given image by measuring the distance of a given pixel from its nearest edge. This is scaled so it is 1 at the center and falls off linearly to 0 at the edges.
  2. Warp: warp the left image using the bilinear filtering method described above, along with its alpha as a 4th channel, onto the right photo. The alpha channel along with this warp will help with the final stitching.
  3. Calculate Size: Similar to the rectification step, send the corners of the left photo through the homography to get the bounding box of the composite image (also taking into account the right photo's corners for the overall calculation of the bounding box).
  4. Place: put both 4-channel images into that box.
  5. Weighted average: blend every pixel = (left color × left alpha + right color × right alpha) / (left alpha + right alpha).

This calculation and dividing by the total left and right alpha ensures that every output pixel is at alpha 1, however, it still mixes when there are overlaps. Divide by one if there is no alpha just to avoid division by zero errors.

With the weighted average, we can have a clean transition. There is some ghosting in some areas, due to manual error when placing the points, or subjects moving between the two images like pedestrians. Ghosting due to manual error is most evident in high frequency regions where single pixel offsets are visible, like very thin lines or the grass in the Memorial Glade. Having correspondence points in a given area makes that area line up better, but it was hard to find correspondence points in the grass of Memorial Glade which is why there is more ghosting there, but the buildings were easy to find points for so they are well aligned.
